# Profile storage, switch checkpoints and permissions

Accounts now has **Storage by profile** and **Profile permissions**. Both load on demand. Account switching from Accounts and Settings uses the same pending-work check.

- **Storage:** The selected account determines the exact browser key and database namespace. The dashboard counts setting keys and local catalog, activity and source records without reading their contents. It measures payload bytes for up to 256 artwork records and 64 print blobs; partial coverage is labeled as a lower bound. It opens only enumerated databases and aborts creation if one disappears during inspection. Protected-record byte totals, unsupported metrics and native caches remain unavailable. The browser's optional site-wide usage/quota estimate is separate. The existing reviewed artwork cleanup is available only for the profile currently open.
- **Switching:** The confirmation lists pending work from Stream Signal, Image Studio settings and recipe drafts, generation, print transforms and native print copy saves, alongside library work. A participant can flush its work, wait for an accepted job, or explain how to resolve a blocker. A failed check keeps the original profile and does not rerun completed checkpoints. The library waits for accepted writes; only after final checks does the tab release its old views and reload. No checkpoint starts a new native job. A submitted print copy can finish while its editor is closed and keeps its receipt in the original profile. An unconfirmed print receipt must be checked or cancelled. Studio recipe names/renames are parked in this tab without committing recipe changes. Stream Signal uses its existing revisioned save and can park a verified recovery copy if a background save fails.
- **Permissions:** Saved browser directory access and profile-specific optional app consents appear together. Listing folders asks only for current read status. A renewal requests read access for the existing handle and never starts a scan or opens a wider picker. Forgetting requires confirmation and replaces only the handle record with a small marker. Catalog rows, marks, native files and other profiles remain intact. Open tabs using the same profile receive a notification and fence new reads; an already open stream in another tab can finish. This removes Realhub's saved reference, not the browser's origin-wide permission. Companion roots and device permissions remain in Settings and are not changed here.

The browser check uses disposable profiles, native IndexedDB/OPFS handles, controlled denial, and a held Companion print response. It does not change real folders, OS permissions or device roots.
